# 股票系统全局审查与收口方案

日期：2026-09-08（Asia/Shanghai）
范围：ACE、推票链路、Finance Work Windows、自由区、TN6/研究知识、 小妍表达层。

## 审查结论

当前系统的主要问题不是缺少更多指标，而是“发现、判断、表达”没有形成同一条实时链路。现有 ACE 已有严格的数据准入、研究卡和风险门；推票研究也已有位置、板块、量价、资金、确认/失效字段；但早盘窗口目前主要记录一次受控刷新和状态，尚未真正做到全市场候选池持续扫描、候选首次出现即留快照、候选变晚后自动降级。因此会出现“方向看对，但送达时已不可参与”。

自由区目前是研究隔离区，桥接状态为 `MAPPED_SHADOW`，没有生产推荐或调度权限。这个边界应保留。自由区可以贡献反例、问题和方法候选，不能直接生成股票候选、改变 ACE 准入或驱动小妍发送。

## 已确认的优点

- ACE 的数据健康门、独立来源、时间戳、`RESEARCH_ONLY` 边界是正确的，不能为了时效绕过。
- 推票框架已明确“位置/预期差优先于涨幅”，并要求确认、失效、流动性和次日路径。
- `core/trade_timing.py` 已提供快照年龄、涨幅过高、封板不可成交和早期转强的行动性判断；它是表达门，不应变成评分器。
- `finance_work_windows.py` 已把动态发现作为现有 Finance 生命周期中的一个任务，避免新增 Scheduler/Daemon。

## 必须修正的缺陷

### 1. 发现时间晚

现有早盘记录能证明某时刻刷新过行情，但没有证明候选池在窗口内被持续扫描，也没有 `first_seen_at`、`source_timestamp` 与每次快照的实际候选内容。没有这些字段，就无法审计“何时第一次形成、何时变晚、延迟发生在哪一段”。

### 2. 候选池与排序仍容易追涨

涨幅榜、单日资金或已经走强的样本可以被研究层读取，但必须只作为线索。真正排序应固定为：市场状态 → 板块扩散 → 竞价/开盘承接 → 分时量价 → 当日资金连续性 → 位置/赔率 → 次日路径。`LATE_HIGH_MOVE`、`WINDOW_MISSED` 只能阻断进场表达，不能提升攻击等级。

### 3. 研究与表达虽已分文件，仍缺实时交接协议

ACE 研究卡与小妍话术的职责已经分开，但交接必须携带同一份快照、数据时间、行动性状态、确认和失效条件。小妍不能拿旧研究卡重新解释当前上涨，也不能把 `RESEARCH_ONLY` 改写成推荐。

### 4. 自由区重复建设风险

自由区的生态、居民、蒸馏和桥接账本不应再复制一套股票调度器、候选池或发送器。它只保留研究问题、反例和可验证方法；通过独立 ACE 复核后，才可能成为研究规则输入。

### 5. 知识重复与权重幻觉

TN6、均线、RSI、MACD、资金字段和涨幅字段存在高度相关，不能重复加权。TN6 只能作 `context_only` 结构借鉴；未经回测、样本外和滑点/涨停不可成交验证的权重全部标记为研究假设。

## 收口后的唯一主链

```text
一个“提前发现可参与机会”的任务
  → 全市场候选池（线索，不直接推荐）
  → 动态发现窗口（按数据可用性和市场状态推进）
  → 增量刷新（窗口内多次轻量扫描）
  → 首次形成快照与时间戳
  → ACE：事实、结构、位置/价格/预期、赔率、确认/失效
  → 行动性门：仍可参与？否则 TOO_LATE/RESEARCH_ONLY
  → 小妍：只把同一快照转成坚定、条件清楚的话术
  → 发送时间与结果回放
```

全市场候选池、动态时间窗、即时刷新不是三个任务，而是同一任务的三个阶段。小妍是表达出口，不是研究或选股器。

## 需要固化的最小账本字段

`task_id, window_id, observed_at, source_timestamp, snapshot_at, first_seen_at, last_seen_at, symbol, price, change_pct, sector_state, candidate_status, actionability_status, business_thesis, why_now, price_and_odds, confirmation, invalidation, attack_grade, conviction, risk, sent_at, too_late_reason, outcome`。

状态至少包括：`FORMING`、`CONFIRMABLE`、`RESEARCH_ONLY`、`TOO_LATE`、`WINDOW_MISSED`、`NO_A_TODAY`。状态变化要追加记录，不能覆盖首次快照。

## 应保留、合并、重做

- 保留：ACE 数据准入与风险边界、现有 Finance Work Windows、`trade_timing` 行动性门、自由区研究隔离、TN6 仅作先验。
- 合并：所有“早盘扫描/竞价观察/候选发现”合并为一个动态发现任务；所有小群模板合并为小妍单一表达适配器。
- 重做：候选发现器必须从单次状态记录升级为窗口内增量扫描，并写入首次快照；排序必须将涨幅降为结果字段；研究卡与表达层必须共享不可变快照引用。
- 删除/禁止：任何按涨幅榜直接凑两只票、在 9% 以上或封板后使用“上车/介入”语言、自由区直接推送、TN6/单指标自动升级候选的路径。

## 验收标准

用户说“推 2 支票”时，系统先在当前动态窗口内找仍可参与且正在形成确认的候选；每只候选能回答“什么时候首次发现、当时什么价格、现在是否还来得及、什么确认、什么失效”。若没有 A 级机会，输出 `NO_A_TODAY`，可以少于两只。任何数据不足只能输出 `RESEARCH_ONLY`，不能用事后上涨证明提前判断。

本审查未改变生产推荐权限、Telegram 权限或金融数据准入门槛；下一步实现应只补齐候选池、增量刷新和快照账本，并沿用现有 ACE daemon。
