### 无候选时模板

源码的 `_generate_empty_report` 生成：市场波动较大、AI 密切监控、预计明日有更清晰信号、不要盲目追涨。它是唯一已找到的“放弃给票”话术原件。

### 报告话术骨架

源码 `layer4_output` 固定结构为：每票的指标表 → 核心逻辑（动量/均值回归/资金）→ 技术面 → 风险提示；尾部为仓位、止损、止盈、周期四项操作建议。历史实现中有随机降级资金流、未冻结的数据源、硬编码阈值和具体止损/止盈数字，不能继承到 ACE。

## 继承判定

| 历史成分 | 证据等级 | ACE/TG 去向 |
| --- | --- | --- |
| 短开场、先接住人、再讲盘 | 汇编 + 当前 TG 设计一致 | 保留为表达节奏 |
| 个股的方向—逻辑—风险骨架 | 汇编 + 旧报告源码 | 保留，但事实、确认/失效条件优先 |
| 亏损时先安抚、再要成本/仓位 | 汇编 | 保留为关怀和最小必要追问 |
| “技术面共振+资金面确认”“趋势向好” | 运行产物 | 仅在同轮有可核验事实时才能改写使用 |

| 固定止损、止盈、仓位、周期数字 | 旧源码 | 不调用；必须来自本轮经核验证据和 ACE 约束 |
| 内幕、机构席位、主力、庄家等暗示 | 汇编 | 永久禁用；不能作为事实或表达策略 |

| 水军互动、洗理念、用户分层转化 | 汇编 | 永久禁用；不做暗操纵或群体引导 |
| “盈亏自负”固定收尾 | 运行产物 | 不作为固定显示话术；风险用具体条件表达 |

## 已落地的未来可调用层

新增 `core/tg_stock_language.py`，仅提供五类**表达模块**：

- `holding_loss`：套牢/亏损/成本/持仓；先稳住、事实和观察条件分开，不给补仓或割肉口令。
- `single_stock`：代码/解票；采用“方向—逻辑—风险”的手机短段。
- `market_sector`：大盘/板块；先判定抱团、分化或未核验，再讲观察条件。
- `review`：复盘；前提与结果分开，不补造历史事实。
- `pick_request`：推票/选股；无当日核验与 ACE 准入时只给研究框架或数据缺口。

`core/tg_companion.py` 已在 A 股意图识别后按用户问题自动附加至多两条模块。模块不含行情、标的、价格、交易指令、外发能力或权限；原有公开数据边界、允许聊天 ID、输出脱敏和安全拦截仍优先。

## 仍缺的考古材料

若要获得“全量逐句话术”，需要以下任一补证而非 Telegram 加密缓存：

1. 早期 Telegram Desktop 的聊天导出（HTML 或 JSON）；
2. `R1_Core_Library_Pack_v11.zip` 或对应备份中的原始 `话术库/`；
3. 八个原始对话 JSON（目录名已列于本报告）；
4. 任何已脱敏的历史群记录。

拿到后应先导入**隔离的考古索引**，标注来源哈希、日期、场景、可复述状态和禁用原因；不应直接喂给线上模型或作为自动发言模板。
