# 本地 One-API 长期运行原则

## 为什么要这样做

上游协议或桌面端可能出现兼容性回归；如果自动化直接绑定单一上游，业务会随上游一起中断。因此 One-API 作为本地统一入口，隔离上游协议变化，并由 watchdog 负责持续可用性。

## 未来如何避免同类问题

- 故障先按桌面端、协议、Provider、网关、矿池、调度器、脚本分层定位。
- 先盘点现有旁路和已验证资产，再决定是否修原链路。
- 网关健康不能只看端口：必须同时验证 `/v1/models` 和一次最小 Chat Completions。
- 所有恢复都要有退出码、时间戳和失败原因；日志不得写入密钥或敏感正文。
- watchdog 只恢复网关进程，不改变 ACE Admission/Data/Validator/Risk 或外发权限。
- 每次改动前回答：为什么需要它？它是否会引入第二套控制面？重启、进程崩溃、上游失败时是否可验证恢复？

## 验收门槛

1. 登录后网关自动启动。
2. 端口、模型目录和真实最小调用均通过。
3. 手动结束网关进程后，watchdog 自动恢复并留下恢复收据。
4. ACE 本地自动化仍以退出码 0 完成，失败保持原始阻断，不伪造成功。
